# سير عمل الامتحانات والنتائج (Examination & Control Workflow)

## 1. مراحل إعداد الامتحان

```
تعريف العام الدراسي/الترم
        │
تعريف نوع الامتحان (شهري/نصف ترم/آخر ترم...)
        │
ربط المواد بالامتحان (exam_subjects) + الدرجة النهائية لكل مادة
        │
تكوين اللجان (exam_committees) + توزيع الطلاب
        │
توليد أرقام الجلوس (seating_numbers) — فريدة لكل طالب/امتحان
        │
نشر جدول الامتحانات
```

## 2. دورة حياة الدرجة الواحدة (exam_results.workflow_state)

```
   ┌────────┐   المعلم يدخل    ┌───────────┐   المعلم يرسل    ┌──────────┐
   │ (فارغ) │ ───────────────▶ │  Draft    │ ───────────────▶ │Submitted │
   └────────┘                  └───────────┘                  └────┬─────┘
                                                                    │ الكنترول يراجع
                                                                    ▼
                                                             ┌────────────┐
                                                             │  Reviewed  │
                                                             └─────┬──────┘
                                                                   │ الكنترول/الوكيل يعتمد
                                                                   ▼
                                                             ┌────────────┐
                                                             │  Approved  │
                                                             └─────┬──────┘
                                                                   │ نشر النتيجة
                                                                   ▼
                                                             ┌────────────┐
                                                             │ Published  │  ← يظهر للطالب/ولي الأمر
                                                             └─────┬──────┘
                                                                   │ قفل نهائي (بعد فترة الاعتراضات)
                                                                   ▼
                                                             ┌────────────┐
                                                             │  Locked    │  ← لا تعديل إلا بصلاحية خاصة
                                                             └────────────┘
```

### قواعد الانتقال (تُفرض في الـ Worker، ليس في الواجهة فقط)

| من | إلى | من يملك الصلاحية |
|---|---|---|
| (فارغ) → Draft | إدخال أولي | `teacher` (لمواده فقط) |
| Draft → Submitted | إرسال للمراجعة | `teacher` |
| Submitted → Reviewed | مراجعة فنية | `exam_controller` |
| Reviewed → Approved | اعتماد | `exam_controller`, `vice_principal`, `principal` |
| Approved → Published | نشر | `exam_controller` |
| Published → Locked | قفل تلقائي بعد مهلة أو يدويًا | `exam_controller` |
| Locked → أي تعديل | تعديل استثنائي | `super_admin` فقط، مع سبب إلزامي مسجَّل بالكامل في `result_approvals` و `audit_logs` |

## 3. التحقق التلقائي (Validation) قبل السماح بالانتقال لـ Approved

يرفض النظام الاعتماد ويعرض قائمة أخطاء واضحة إذا وُجد:

- درجة أكبر من `grade_components.max_score` المحدد للمادة.
- مادة بلا درجة مُدخلة لطالب مسجَّل فيها.
- طالب مسجَّل في الفصل لكن غير موجود في `exam_subjects` (مادة بدون طالب أو العكس).
- درجات مكررة لنفس الطالب/المادة/الامتحان (unique constraint + فحص منطقي).
- طالب بدون `seating_number` مرتبط بالامتحان.
- امتحان غير مرتبط بـ `academic_year_id` أو `term_id` صالح.

## 4. حساب النتيجة النهائية

لكل طالب ولكل مادة:

```
مجموع المادة = Σ (درجات المكوّنات المفعّلة في grade_components)
النسبة = (مجموع المادة / الدرجة النهائية للمادة) × 100
التقدير = يُحسب من جدول grade_scale القابل للتخصيص (مثال: 90+=ممتاز)
حالة المادة = ناجح/راسب بناءً على حد النجاح القابل للتخصيص لكل مادة
```

على مستوى الطالب:

```
المجموع الكلي = Σ مجاميع كل المواد
النسبة العامة = (المجموع الكلي / مجموع الدرجات النهائية لكل المواد) × 100
الحالة العامة = تُحسب حسب سياسة الترسيب القابلة للتخصيص
  (مثال: الرسوب في مادتين أساسيتين أو أكثر = "له دور ثانٍ")
```

كل هذه الحدود والسياسات تُخزَّن في `school_settings` / `grade_components` /
جدول `promotion_rules` القابل للتعديل من `super_admin`، وليست ثابتة في الكود.

## 5. إصدار الشهادة

```
Published/Locked Result → طلب إصدار شهادة
        │
Worker يرسل بيانات الطالب+النتيجة إلى GAS
        │
GAS ينسخ قالب Google Docs الرسمي → يملأ الحقول → يصدّر PDF
        │
GAS يرفع الملف لمجلد Certificates على Drive
        │
Worker يحفظ رابط الملف + ينشئ verification_code فريد (QR)
        │
الطالب/ولي الأمر يحمّل PDF، وأي طرف ثالث يتحقق عبر
GET /api/certificates/verify/:code
```
